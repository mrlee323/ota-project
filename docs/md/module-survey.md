모듈 수가 근거 없이 정해지면 구현 중반에 반드시 흔들린다.

> 마이리얼트립은 조사 시점에 `/events` 가 종료(Service unavailable), 트립닷컴은 딜 페이지 404 로 표본에서 제외했다.

## 2. 발견

### F1. 이미지 의존이 ~90% 다

여기어때 6건에서 «기능이 있는» 블록은 다 합쳐 **32개**뿐이다.
나머지 약 280장은 전부 디자이너가 자른 이미지 슬라이스다.

```
쿠폰 3 · 탭 전환 3 · 특징 캐러셀 5 · 비디오 1 · CTA 20  =  32
```

대표 사례 — 브랜드 위크(6355)는 이미지 46장에 본문 텍스트가 **330자**다.
호텔 이름조차 `<img alt="류큐 호텔 앤 리조트 나시로 비치">` 로만 존재한다.
즉 **페이지 빌더가 아니라 이미지 업로더**로 운영되고 있다.

> 이게 이 프로젝트가 풀려는 문제의 크기다. 모듈을 만든다는 건
> 저 280장 중 몇 장을 구조화된 블록으로 되찾아오느냐의 문제다.

### F2. 6건 전부에 공통으로 있는 블록이 4종이다

| 블록 | 출현 | 비고 |
|---|---|---|
| 상단 비주얼(hero) | 6/6 | `event-visual` / `event-top` |
| CTA 버튼 | 6/6 | 총 31회. 최다 출현 블록 |
| 주의사항 | 6/6 | **유일하게 텍스트로 존재하는 콘텐츠** (391~1,234자) |
| 앱 유도 푸터 | 6/6 | 고정 — 모듈이 아니라 레이아웃으로 봐야 한다 |

주의사항이 6건 전부에서 이미지가 아닌 실제 텍스트라는 게 중요하다.
**법적 고지라 검색·복사가 돼야 하기 때문**이다. 모듈로 만들 때 이 성질을 유지해야 한다.

### F3. 반복 단위가 뚜렷하다

브랜드 위크(6355)의 본문은 호텔 4곳이 **같은 4블록 묶음**으로 반복된다.

```
[호텔명 이미지] → [특징 캐러셀 3~5장] → [가격·설명 이미지] → [CTA "지금 구매하기"]   × 4개 호텔
                                                        ↓
                                        [지역 배너 + 지역별 CTA]  × 5개 지역
```

이 반복이 곧 «다호텔 템플릿» 이다. 담당자가 조립할 단위는 개별 이미지가 아니라 **이 묶음**이다.

### F4. 기능 블록은 5종에서 멈춰 있다

가장 기능이 많은 페이지(스페인, 6267)조차 종류는 5종이다.

| 블록 | 개수 |
|---|---:|
| CTA (`btn-wrap` + `btn-wrap-overseas`) | 11 |
| 탭 전환 슬라이드 | 3 |
| 쿠폰 (A/B/C 3종) | 3 |
| 특징 캐러셀 | 1 |
| 비디오 | 1 |
| **이미지 슬라이스** | **30** |

49개 단위 중 30개가 이미지다. 기능 블록을 아무리 늘려도 **이미지 모듈이 없으면 실제 페이지를 재현할 수 없다.**
→ `image` 는 «임시방편» 이 아니라 **1급 모듈**로 넣어야 한다.

### F5. 야놀자는 정반대 극이고, 그쪽이 더 앞서 있다

NOL 특가 허브는 텍스트가 **5,974자**다. 여기어때 6건 전체 합보다 많다.
구조가 `[섹션 제목 + 부제] → [상품 카드 캐러셀]` 의 반복이고, 카드가 **실데이터**다.

```
특가 TOP 3        → 카드 3 (가격 824,000 → 64% → 299,000원~, 뱃지 "숙페셜데이")
인천-도쿄 항공권   → 카드 6
이번주 해외숙소    → 카드 6
...  총 11 섹션
```

할인율·최저가·뱃지가 이미지가 아니라 값이라 **가격이 바뀌면 페이지가 저절로 맞는다.**
여기어때 방식에서는 가격이 바뀌면 디자이너가 이미지를 다시 만들어야 한다.

> **가장 큰 효용은 «페이지를 조립하는 것» 이 아니라 «카드를 데이터로 만드는 것» 에 있다.**
> 조립 UI 없이 카드만 정확해도 운영 비용의 상당 부분이 사라진다.

## 3. 도출 — 모듈 8종 (v1 은 6종)

출현 근거가 없는 모듈은 만들지 않는다.

| 모듈 | 근거 | v1 |
|---|---|:--:|
| `hero` | 7/7 전부 | ✅ |
| `image` | 이미지 슬라이스 ~280개. 없으면 실사 페이지 재현 불가 (F4) | ✅ |
| `cta` | 6/6, 총 31회 — 최다 출현 | ✅ |
| `notes` | 6/6, 유일한 텍스트 콘텐츠 (F2) | ✅ |
| `section-title` | 야놀자 11섹션. 여기어때는 같은 역할을 이미지로 때움 | ✅ |
| `hotel-card-list` | 야놀자 전 섹션. 효용이 가장 큰 모듈 (F5) | ✅ |
| `feature-carousel` | 3/6 (6355·6267·4457) | v2 |
| `coupon` | 1/6 (6354·6267), 쿠폰 유형 전용 | v2 |

**v1 = 6종.** 이 6종이면 표본 7건의 구조를 전부 표현할 수 있다 (캐러셀·쿠폰은 `image` 로 강등해 표현).

## 4. 도출 — 템플릿 4종

| 템플릿 | 구성 | 커버 |
|---|---|---|
| T1 브랜드·다호텔 | `hero` → (`image`→`image`→`cta`) × N → `notes` | 6355, 6322 |
| T2 목적지 테마 | `hero` → `image` → (`image`→`cta`) × N → `notes` | 6267, 4457 |
| T3 허브·특가 | `hero` → (`section-title`→`hotel-card-list`) × N → `notes` | 야놀자, 4457 |
| T4 단독·제휴 | `hero` → `image` → `notes` | 6308, 6354 |

**4종으로 표본 7/7 (100%) 커버.**
템플릿 수가 한 자릿수 초반에서 멎는다는 게 이 실사의 결론이다 — 페이지는 다양해 보여도
구성의 골격은 몇 개 안 된다.

## 5. 이 실사가 설계에 거는 제약

1. **`image` 모듈을 1급으로 넣는다.** 이게 없으면 실제 페이지를 하나도 재현 못 한다 (F4)
2. **`notes` 는 이미지가 아니라 텍스트여야 한다.** 법적 고지 성격 (F2)
3. **`hotel-card-list` 의 가격·할인율은 값으로 받는다.** 여기가 효용의 원천 (F5)
4. **반복 묶음을 조립 단위로 다룬다.** 개별 이미지를 4개씩 붙이게 하면 캔버스가 이미지 업로더로 회귀한다 (F3)
5. **모듈 수를 6종에서 시작한다.** 근거 없는 7번째 모듈을 만들지 않는다

## 6. 방법의 한계 (다음에 보완할 것)

- **표본이 여기어때에 쏠려 있다** (6/7). 마이리얼트립·트립닷컴이 접근 불가였다
- **구성 단위의 단위가 페이지마다 다르다.** 어떤 페이지는 본문 전체가 `event-detail` 하나로 묶여 있어(6308·6354) 블록 수를 과소 집계했다. 이미지 장수는 정확하다
- **모바일만 봤다.** PC/모바일 구성이 다를 수 있다
- **N=7 이다.** 템플릿 4종 커버율 100% 는 «7건 기준» 이라는 뜻이다
