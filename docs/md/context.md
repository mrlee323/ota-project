# 배경과 결정 이력 — 다른 세션이 먼저 읽을 것

**왜 이 문서가 있나** — 다른 문서엔 **결론**만 있다.
«무엇을 버렸는지, 왜 버렸는지» 를 모르면 새 세션이 이미 폐기된 안을 다시 제안한다.
실제로 이 프로젝트의 설계는 여러 번 틀렸다가 고쳐졌고, 아래가 그 기록이다.

---

## 1. 이 프로젝트가 무엇인가

**MD(기획전) 페이지를 담당자가 코드 없이 만들 수 있게 하는 개인 프로젝트.**

목적이 두 가지다.

1. **디자인시스템 + MD 자동화의 «프로세스» 를 정의하고 검증한다.**
   작동하는 것을 만들어 보는 게 목적이다.
2. **이력에 쓸 수 있는 결과물을 남긴다** — 특히 AI 활용.
   그래서 **측정 기록이 코드만큼 중요하다** (plan.md §7).

### 자주 어긋나는 전제

| 오해 | 사실 |
|---|---|
| 이 코드가 어딘가로 이식된다 | **아니다.** 프로세스를 정의해 보는 것이다. 코드 이식이 목적이 아니다 |
| 참고할 원본 구현이 있다 | 참고만 한다. **똑같이 만들 필요 없다.** 더 나은 구조가 있으면 그쪽으로 간다 |
| MCP 가 캔버스를 대체한다 | **아니다.** 캔버스는 반드시 만든다. 담당자가 직접 세팅·수정하는 화면이 없으면 아무것도 안 된다 |

### 공개 레포다

`mrlee323/ota-project` 는 **public** 이다.

- 회사·사내 관련 서술을 문서나 코드에 남기지 않는다
- 키를 커밋하지 않는다 (`.gitignore` 에 `.env*` 확인됨)
- 이 규칙은 이미 한 번 위반됐다가 걷어냈다 — 반복하지 않는다

---

## 2. 실사가 근거다 — 감으로 정한 게 아니다

모듈 6종·템플릿 4종은 **공개 기획전 7건을 DOM 으로 직접 세어** 나왔다 (module-survey.md).

핵심 수치 셋 —

| | |
|---|---|
| **이미지 의존 ~90%** | 여기어때 6건에서 기능 있는 블록은 32개뿐, 나머지 ~280장이 이미지 슬라이스 |
| **주의사항만 텍스트** | 6/6 전부. 법적 고지라 검색·복사가 돼야 해서 |
| **야놀자는 정반대** | 텍스트 5,974자. 카드가 실데이터라 가격이 바뀌면 페이지가 저절로 맞는다 |

**여기서 나온 못 미룰 제약 셋**

1. **`image` 는 1급 모듈이다.** 가장 기능이 많은 페이지도 49블록 중 30이 이미지다 — 이미지 모듈 없이는 실제 페이지를 하나도 재현 못 한다
2. **`notes`(주의사항)는 텍스트여야 한다.** 이미지로 만들면 안 된다
3. **`hotel-card-list` 의 가격은 값으로 받는다.** 여기가 효용의 원천이다

**실사의 한계도 기록돼 있다** — N=7, 여기어때 6건 쏠림, 모바일만. 표본을 늘리면 재검토한다.

## 3. 폐기된 안 — 다시 제안하지 말 것

### ❌ MD 를 기존 `showcase` 위에 얹기

**가장 먼저, 가장 크게 틀린 것.** 이 레포에 `showcase`(메인 화면의 지역 특가 구좌)가
이미 있어서 그 위에 MD 를 얹는 안을 냈다가 폐기했다.

**MD 는 별도 도메인이다** — 별도 테이블(`md_pages`) · 별도 라우트(`/md/[slug]`) · 별도 어드민.
`showcase` 에서 재사용하는 건 호텔 카드의 **표시 규칙** 정도다.

> `src/domain/hotel/showcaseTypes.ts` 와 `showcase` 도메인을 **수정하지 않는다.**

이 착각의 부산물로 «기존 쇼케이스를 모듈로 변환해 라운드트립 diff 0» 이라는 관문을
만들었는데, 대상이 없으므로 그것도 폐기됐다. 지금 관문은 **AC-1(실사 3건 구조 재현)** 이다.

### ❌ HTML 템플릿 + 문자열 조립기 (DOMParser)

어드민과 서비스가 **같은 Next 앱**이라 React 컴포넌트를 직접 공유할 수 있다.
문자열 조립기는 스택이 갈린 환경에서 필요한 우회다 — 여기엔 그 원인이 없다 (D1).

### ❌ 그룹 모듈 (`hotel-section` 이 안에 4블록을 품는다)

모듈 정의가 **재귀**가 되고, 렌더러·검증·폼 자동생성이 전부 재귀를 다뤄야 한다.
FR-1.3(모듈 추가 = 수정 2곳)이 깨진다.

### ❌ 섹션 템플릿 (`scope='section'`)

반복 묶음을 «부분 템플릿» 으로 푸는 안. **관리 대상이 하나 늘어난다** —
섹션마다 CRUD·즐겨찾기·공유·소유자가 붙고 페이지 템플릿과 한 목록에 섞인다.
계층이 `template → module` 에서 `template → section → module` 로 깊어진다.

> **계층은 `template → module` 2단계를 유지한다.** 중간 단계를 만들지 않는다.
> 반복 묶음은 **블록의 `group` 태그**로 푼다 (design.md §5).

### ❌ Anthropic SDK · `zodOutputFormat` · `claude-opus-5`

LLM 을 새로 세우는 안이었다. **이 레포에 이미 Gemini + FLUX + Supabase 업로드 배관이 있다.**
새 모델·새 키를 세우지 않는다.

### ❌ Gemini 를 그대로 쓰기 → ❌ Cerebras → ✅ Google AI Studio

두 번 뒤집혔다. 기록해 둔다.

1. 기존 Gemini SDK 를 그대로 확장 → 무료 한도가 작아 보여 폐기
2. **Cerebras** 로 결정 → 실제 계정에서 **모든 모델이 402**, 활성화에 카드 등록 요구 (2026-09-05)
3. **Google AI Studio 의 OpenAI 호환 엔드포인트**로 확정 —
   `https://generativelanguage.googleapis.com/v1beta/openai/` · `gemini-2.5-flash`

**교훈** — 공급자를 코드에 박지 않은 설계(`baseURL` 환경변수)가 값을 했다.
두 번 갈아탔지만 코드는 한 줄도 안 고쳤다. 무료 티어 정보는 조사 시점과 실제가 다를 수 있으니
**결정 전에 실제 호출로 확인한다.**

### ❌ tool use 로 페이지 JSON 만들기

tool use 는 모델이 도구를 여러 번 고르는 **에이전트 루프**용이다.
L1 은 요청 1회 → JSON 1회라 루프가 없다 → **structured output** 이 맞다.

### ❌ MCP 에 이미지 생성 도구 두기

나머지 MCP 쓰기 도구는 전부 «DB 에 draft 쓰기» 라 호출 비용이 0 인데
이미지만 외부 API 를 불러 **비용이 서버에 남는다.**
MCP 에 두면 원격에서 우리 지갑을 여는 도구가 되고, 그것 하나 때문에
사용자당 일일 상한 같은 장치가 필요해진다.

> **이미지 생성은 캔버스 전용이다** (llm.md §4). MCP 도구로 만들지 않는다.

### ❌ Draft Mode 로 공개 라우트에서 미리보기

`draftMode()` 는 쿠키를 읽는다. 쿠키를 읽으면 Next 가 페이지를 동적으로 판정하고,
ISR 로 빌드된 페이지에서 그러면 **프로덕션에서 런타임 500** 이 난다
(`Page changed from static to dynamic at runtime, reason: cookies`).
**dev 서버는 이 검사를 하지 않아 로컬에서는 통과한다** — 배포하고 나서야 드러났다.

미리보기는 `/md/[slug]/preview` 로 나누되 **화면 컴포넌트(`MdPageView`)를 공유한다**
(design.md §6). 라우트가 갈린 이유는 캐시 정책이지 화면이 달라서가 아니다.

### ❌ 레지스트리(사설 npm) 배포

디자인시스템 경계는 재현하되 레지스트리는 **버전 협상·배포 지연 비용만 있고 검증할 게 없다.**
pnpm 워크스페이스로 가르면 경계는 서고 비용은 0 이다 (D8).

## 4. MCP 는 «비용» 때문이 아니다

흔한 오해라 따로 적는다. MCP 를 붙이는 **1번 이유는 선택 문제**다.

| # | 문제 | 왜 |
|---|---|---|
| **P1** | **모듈이 100개가 되면 담당자가 못 고른다** | 팔레트 스크롤은 20개쯤에서 무너진다. 결국 아는 3~4개만 반복해서 쓰게 되고, 모듈을 100개 만든 의미가 사라진다 |
| **P2** | **어떤 구성이 어울리는지 판단을 못 한다** | 디자이너가 하던 판단이다. 빼기만 하고 대신할 게 없으면 결과물이 나빠진다 |
| **P3** | **이미지를 못 만든다** | 모듈을 늘려도 히어로 배경 한 장은 여전히 필요하다 |

비용이 호출자에게 넘어가는 건 **덤**이다. 근거 순서를 바꾸지 않는다.

그리고 P1 때문에 **`list_modules` 로는 안 된다** — 모듈 정의 하나가 300~600 토큰이라
100개면 매 대화마다 30~60K 토큰이 나간다. 그래서 2단계다:
`search_modules`(요약만) → `get_module`(전체 정의).

## 6. 반복되는 실수 — 체크리스트

새 세션이 하기 쉬운 실수들이다.

- [ ] `showcase` 위에 얹으려 한다 → **별도 도메인이다**
- [ ] 캔버스를 안 만들고 MCP 로 때우려 한다 → **캔버스는 반드시 만든다**
- [ ] 모듈을 7개 이상 만든다 → **AC-1 통과 전 금지**
- [ ] 블록별 편집 폼을 손으로 짠다 → **정의로 자동 생성**해야 스키마 층이 의미가 있다
- [ ] `z.record(z.unknown())` 을 쓴다 → zod4 는 **키 스키마 필수**
- [ ] 프롬프트에 모듈 설명을 손으로 쓴다 → **`MODULE_DEFS` 를 직렬화**한다. 모듈을 늘려도 프롬프트를 안 고치는 게 요점
- [ ] AI 이미지에 글자가 들어간다 → **실사 F1 의 문제를 그대로 재생산한다.** 고정 제약 4줄 필수
- [ ] 성과 측정을 나중으로 미룬다 → **P3 에 묶여 있다.** 미루면 영영 안 붙는다
- [ ] 자유 입력(`free`) 필드를 늘린다 → 지금 3개뿐이다. 늘면 페이지가 다시 제각각이 된다
- [ ] 회사 얘기를 문서에 쓴다 → **공개 레포다**
- [ ] LLM 호출에 `max_tokens` 를 짜게 준다 → thinking 모델은 JSON 이 잘려 «스키마 위반» 처럼 보인다
- [ ] ISR 페이지에서 쿠키를 읽는다(`draftMode`·세션) → **프로덕션에서만 500 이 난다.** 세션이 필요하면 라우트를 나눈다

## 7. 「스키마가 심장」이 무슨 뜻인가

이 프로젝트가 증명하려는 한 문장이다. **모듈 정의(`MODULE_DEFS`)가 데이터이고, 한 소스가 네 곳에 쓰인다.**

```
        MODULE_DEFS (모듈 정의 = 데이터)
              │
    ┌─────────┼──────────┬──────────────┐
    ▼         ▼          ▼              ▼
 저장 검증  L1 출력 스키마  어드민 폼   MCP 도구 스키마
```

모듈을 하나 추가하면 네 곳이 **저절로** 따라온다.
그래서 성공 판정이 «모듈 1종 추가 = 변경 파일 2개»(AC-2)이고,
3개가 되는 순간 설계가 샌 것이므로 **되돌린다.**

이 숫자가 이력에서 말할 수 있는 것의 핵심이다.
